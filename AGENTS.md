# Инструкции по разработке

- Начните с [карты проекта](PROJECT_MAP.md). Откройте точку входа, связанный модуль и ближайший тест. Ищите по имени функции или ключу JSON через `rg`. Читайте нужный раздел README по заголовку.
- Для обычных задач пропускайте снимки данных, HTML целиком, шрифты и коммиты бота. Для JSON сначала смотрите схему, поля и несколько записей. Для интерфейса уточните, какую страницу меняете, и проверьте соответствующий участок соседней версии.
- Переиспользуйте сбор, форматирование и Telegram-обёртки из `common.py`. При изменении скоринга сверяйте Python и JS тестом паритета. При изменении публикации сохраняйте совместимость полей JSON с Pages и Worker.
- В `docs/` и публичных коммитах допустимы только публичные данные. Секреты и WATCHLIST держите вне исходников, фикстур и логов. Не коммитьте локальные результаты демо, в том числе `.digest_send.json`.
- Проверяйте по [.github/workflows/checks.yml](.github/workflows/checks.yml). Для проверки без сети используйте фикстуры и `--demo` в отдельной копии. `DRY_RUN=1` подавляет доставку через штатные обёртки, но сам по себе допускает запросы к источникам и запись файлов.
- Разделяйте изменения кода и обновления снимков. Перед PR проверьте список файлов и укажите, какие автономные проверки прошли.
